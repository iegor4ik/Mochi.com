## 2. Что строим (описание игры)

2D-мир с видом сверху, спрайты мира — из PNG-картинок. Персонажи — **«кругляшки»**:
круглое тело, у которого **две ручки** (два маленьких овала по бокам), **внутри круга —
фото пользователя** (аватар с аккаунта сайта), **под шариком — никнейм**.

- Один сервер для подключения — **«Хаб»**.
- **Чат**: сообщение игрока показывается **пузырём над его персонажем** и
  **дублируется в панель чата** (сбоку/справа сверху — на твоё усмотрение; размести
  как удобно сейчас, вынеси разметку панели в отдельный блок/файл, чтобы позже легко
  менять вариации расположения).
- **Стены** — коллизии.
- **Переход в другую локацию** — дверь/портал (§10).
- **Объекты взаимодействия**: взять в руку, положить, бросить (§6).
- Подключение **нескольких игроков** одновременно.
- Аватар и ник — **с аккаунта сайта** (§8). Игровой регистрации нет: вход токеном форума.
- «Почва» для будущего редактирования спрайтов (вставка фото и т.п.) — подготовить,
  НЕ реализовывать (§9).

## 4. БД игры и сид

Миграция `001_init.sql` (идемпотентная, IF NOT EXISTS, журнал `schema_migrations`):

- `locations` — id, slug (uniq), name, map JSONB, created_at;
- `world_objects` — id, location_id (FK→locations, ON DELETE CASCADE), def_key
  (тип объекта), x, y, vx, vy, taken_by INTEGER NULL (user_id; **без FK** — базы разные),
  updated_at;
- `chat_messages` — id, location_id, user_id, username, text, created_at;
  индекс (location_id, created_at DESC).

`locations.map` — упрощённый встроенный формат (загрузка пользовательских Tiled-карт —
за пределами MVP, но валидатор JSON на входе всё равно сделай):

```json
{
  "width": 1600, "height": 900,
  "walls": [ { "x": 0, "y": 0, "w": 1600, "h": 24 } ],
  "exits": [ { "id": "door-1", "x": 1500, "y": 420, "w": 48, "h": 64,
               "to": "room2", "spawn": "default" } ],
  "spawns": [ { "id": "default", "x": 200, "y": 450 } ]
}
```

Сид (`npm run seed`): локация `hub` «Хаб» (основная) и `room2` «Пустая комната»
(техническая, для проверки перехода) + 5–8 объектов типов `ball`, `box`, `stone`.
Сид идемпотентен (ON CONFLICT DO NOTHING), повторный запуск безопасен.

## 5. WS-протокол

JSON-кадры `{type, ...}`. Подключение — `…/ws`; **первый кадр обязательно `auth`**,
до него ничего не принимается, таймаут 10 с → close (4401). Токен в URL не передавать.

Клиент → сервер:

- `{type:'auth', token}` — JWT форума;
- `{type:'join', location:'hub'}`;
- `{type:'move', x, y}` — целевая точка, 10–15 Гц;
- `{type:'chat', text}` — ≤ 300 символов, trim;
- `{type:'interact', action:'take'|'put'|'throw', objectId, dir?}` — `dir` нужен для броска.

Сервер → клиент:

- `{type:'auth_ok', user:{id, username, avatar}}`;
- `{type:'join_ok', you, location:{slug,name,map}, players, objects, chatHistory}`;
- `{type:'snapshot', players, objects}` — 10 Гц, только AOI-зона получателя;
- `{type:'player_join', player}` / `{type:'player_leave', userId}`;
- `{type:'chat', userId, username, x, y, text}`;
- `{type:'object_state', object}` — любое изменение объекта;
- `{type:'error', message}`; `{type:'closing'}`.

`players[*] = { userId, username, avatar, x, y, holding?:objectId, dir }`.
`objects[*] = { id, def_key, x, y, taken_by? }` (vx/vy — только в полёте).

## 6. Правила realtime (обязательные)

1. **Авторитарность**: сервер валидирует скорость (макс ~220 px/s + допуск), телепорт,
   границы карты и коллизии со стенами; нарушение → кламп к допустимой позиции.
2. **AOI**: снапшоты и chat-события рассылаются только игрокам в радиусе ~600 px.
3. **Объекты**: `take` запрещён, если `taken_by` уже установлен (первый взявший
   получает); объект «в руке» рендерится только у держащего, остальным скрыт;
   `put` — у ног держащего; `throw` — по `dir`, начальная скорость ≤ 500 px/s,
   полёт с затуханием, остановка у стены (не сквозь), финальная позиция
   валидируется сервером и рассылается всем.
4. **Лимиты**: чат ≤ 5 сообщений / 10 с на соединение; interact ≤ 5/с; `move` чаще
   20 Гц — игнорировать.
5. **Heartbeat**: ping/pong ~30 с, мёртвые соединения закрываются.
6. **Персистентность**: объекты (x, y, vx, vy, taken_by) — debounce-запись в БД
   (~раз в 5 с при изменениях) и при shutdown; чат — сразу в БД.
7. **Graceful shutdown** (SIGTERM): `{type:'closing'}` всем → flush → закрыть WS/HTTP
   → `process.exit(0)`; в compose — `restart: unless-stopped`.

## 7. Фронтенд

- Phaser 3 одним `<script>`: в dev допустим CDN
  (`https://cdn.jsdelivr.net/npm/phaser@3/dist/phaser.min.js`); если сможешь положить
  файл в `js/game/vendor/phaser.min.js` — положи и подключай его. Никакого npm/сборки.
- REST-вызовы игры (`/api/me`, `/api/locations`, история чата) — `fetch` на
  `GAME_API_BASE` с заголовком `Authorization: Bearer <localStorage.mochi_token>`.
  `api.js` **не редактировать** (его база — основной `/api`).
- Управление: WASD/стрелки; клавиши вынеси в `config.js`.
- **Кругляшка** (`character.js`): тело — круг; внутри — аватар пользователя, обрезанный
  по кругу (нет аватара — плейсхолдер-цвет); **две ручки** — маленькие эллипсы по бокам,
  при ходьбе меняют позицию (двухкадрового «шагания» достаточно); **ник — текст под
  телом**.
- **Чат** (`chat.js`): панель (список сообщений + инпут, Enter — отправка); входящее
  сообщение рисует пузырь над персонажем на ~6 с и добавляется в панель. HTML-слой
  поверх канваса с позиционированием по координатам камеры — допустимо; весь текст
  только через `UI.esc()`.
- **Объекты**: рядом с объектом — подсказка «E — взять»; в руке рисуется у ручки;
  положить — Q; бросить — клик мышью (направление от персонажа к точке клика).
- **Стены**: рисуются из `map.walls` (спрайтом из манифеста или цветом-плейсхолдером).
- **Переход**: дверь из `map.exits`; при E рядом — leave + join, оверлей «Переход…».
- Стили `game.css` — в стиле M-o-chi на токенах `style.css`; тема применяется через
  `theme.js` (смена темы на форуме меняет и игру).

## 8. Аватары и профиль (связь с аккаунтом сайта)

- `GET /api/me` (game-server): токен → проверка → профиль из кэша или
  `MAIN_API_URL + /api/internal/user/:id` → `{id, username, avatar, role}`.
- Внутренний эндпоинт (основной сервер, `routes/internal.js`): `requireAuth`; отдаёт
  **только** `{id, username, avatar, role, is_banned}`; если задан env
  `INTERNAL_API_KEY` — требует заголовок `X-Internal-Key` (game-server шлёт его же
  значением).
- `is_banned` → отказ в auth-кадре с понятной ошибкой («Аккаунт заблокирован»).
- Аватар — путь вида `/uploads/…` (тот же домен): в prod грузится напрямую; в dev —
  префикс основного origin из `config.js` (`MAIN_ORIGIN = 'http://localhost:3000'`).
- Кэш профилей 5–15 минут (§5 GAME_INTEGRATION.md); активные сессии переживают
  недоступность основного API, новые подключения — нет.

## 10. Локации и переходы

- Один процесс = один сервер «Хаб»; внутри — комнаты-локации (`room.js`).
- MVP-локации: `hub` (основная) и `room2` (техническая, для проверки перехода).
- Переход = leave текущей + join новой **в одной WS-сессии**; спавн из
  `exits[].spawn` целевой карты.
- `GET /api/locations` — список локаций (пригодится будущему лобби; в MVP можно
  не использовать).

## 11. Этапы работ и проверки

Выполняй строго по порядку; после каждого этапа — проверка и краткий отчёт.

1. **Каркас**: `game-server/` (package.json, index.js, config/db.js, health).
   Проверка: `npm start` → `curl http://localhost:3001/api/health`.
2. **БД**: миграция + сид. Проверка: `npm run migrate` дважды без ошибок; `npm run seed`.
3. **Auth**: middleware JWT + `internal.js` на основном сервере + `/api/me`.
   Проверка: с токеном форума — 200 с профилем; без токена — 401.
4. **WS-каркас**: auth-кадр, heartbeat, комнаты. Проверка: два браузера (или два
   ws-клиента) видят join/leave друг друга.
5. **Движение**: move, валидация скорости/границ, коллизии стен, AOI-снапшоты.
6. **Чат**: пузырь над персонажем + панель + история 20 сообщений при входе.
7. **Объекты**: take/put/throw с валидацией и персистентностью.
8. **Переход**: hub ↔ room2 у обоих игроков, спавн в заданной точке.
9. **Фронт-полировка**: тема, `UI.esc()` везде, плейсхолдеры-ассеты, dev-конфиг.
10. **Инфраструктура**: `Dockerfile.game` + сервисы compose + `.env.example`.
    Если Docker запущен: `docker compose up -d game-db game` и проверка изоляции
    `docker kill mochi-game` → форум жив; иначе пометь пункт «требует ручного прогона».

Команды dev (Windows): `docker compose up -d db game-db`; в `server/` — `npm run dev`;
в `game-server/` — `npm run dev`; форум на http://localhost:3000 (сначала залогиниться),
игра — http://localhost:3000/game.html.
